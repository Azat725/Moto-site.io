Прочитайте файл целиком перед любой правкой. Человеческая версия правил — [CONTRIBUTING.md](CONTRIBUTING.md), обзор проекта — [README.md](README.md).

## 1. Контекст проекта
- **Что это:** сайт мотосалона **IV&AX MOTO** (Нижнекамск, РФ). Витрина мотоциклов: каталог, страницы моделей, тест-драйв, рассрочка с калькулятором, контакты, юридические документы.
- **Стек:** чистые HTML + CSS + JS, без фреймворков и внешних npm-пакетов. Страницы собирает из шаблонов генератор на Node.js (`scripts/build.mjs`). Нужен Node 18+.
- **Язык сайта:** русский. Код и имена файлов — латиница, комментарии и тексты интерфейса — по-русски.
- **Палитра:** красный `#E10600` (текст красным на тёмном — `#FF3B30`), белый, чёрный. Токены — `css/tokens.css`. Не вводить новые цвета без согласования.
- **Референс по структуре:** elmoto74.ru (только структура блоков; тексты, картинки, код оттуда не копировать).
- **Тексты и картинки сейчас — заглушки.** Модель Yamaha YZF-R3 2026 сделана по мотивам объявления Avito, цена условная; остальные 7 моделей — демо с вымышленными названиями. Фото с Avito и других сайтов не использовать.
- **Хостинг:** GitHub Pages из ветки `main`, корень: https://azat725.github.io/Moto-site.io/ . Репозиторий: https://github.com/Azat725/Moto-site.io (публичный). Пока домен тестовый, в `site.config.json` стоит `"noindex": true` — сайт закрыт от поисковиков; **не снимайте флаг без прямого указания владельца**.
- **Владелец проекта** — Azat725 (GitHub). Партнёр-разработчик добавляется как collaborator (`scripts/invite-partner.ps1`).

## 2. Ветки и порядок работы (обязательно)
| Ветка | Правило |
|-------|---------|
| `main` | Стабильная и **публикуемая**: всё, что попало в `main`, сразу выкладывается на GitHub Pages. Прямых коммитов нет. |
| `dev` | Рабочая ветка. Вся работа ведётся здесь (или в `feature/<название>`, созданной от `dev`). |

1. Перед началом: `git fetch origin && git checkout dev && git pull --ff-only`. Если находитесь не на `dev` — переключитесь.
2. Работайте в `dev` либо в `feature/...` → затем слейте в `dev`. **Никогда не коммитьте в `main` напрямую.**
3. Мелкие осмысленные коммиты по схеме `feat: …`, `fix: …`, `content: …`, `docs: …`, `chore: …`, `style: …`.
4. После каждой правки в `src/`, `data`, `site.config.json` или `scripts/lib/` выполните `npm run build` и **закоммитьте сгенерированные файлы вместе с исходниками**.
5. **Вливать `dev` в `main` можно только после успешного тестирования** (раздел 3). Слияние — fast-forward или Pull Request `dev → main`:
   ```bash
   git checkout main && git pull --ff-only && git merge --ff-only dev && git push origin main && git checkout dev
   ```
   Если fast-forward невозможен — сначала подтяните `main` в `dev`, повторите тесты, затем сливайте. Никаких `push --force`, `reset --hard` по общим веткам и переписывания истории `main`.
6. В отчёте владельцу кратко укажите: что изменено, какие тесты прогнаны, влито ли в `main`.

## 3. Тестирование перед влитием в `main`
Обязательный минимум — всё из списка должно быть выполнено и зелёным:
- [ ] `npm run check` → `OK: … проблем нет` (сборка, битые ссылки/ресурсы, `title`/`description`/один `h1`/`canonical`, валидность JSON-LD, уникальные `id`).
- [ ] `npm start` и ручной просмотр в браузере (http://localhost:5173) изменённых страниц на ширине **375 / 768 / 1280** px: нет горизонтальной прокрутки, нет наложений.
- [ ] Консоль браузера без ошибок и предупреждений; нет 404 в сети.
- [ ] Анимации не ломают контент: проверить без JS (контент виден), с `prefers-reduced-motion`.
- [ ] Затронуты формы/cookie/фильтры/калькулятор — проверить их сценарии вручную (пустая отправка → ошибки; без согласия форма не уходит; cookie-баннер сохраняет выбор).
- [ ] `git status` чистый, сгенерированные файлы закоммичены, секретов в диффе нет.
Если не можете запустить браузер — честно напишите об этом в отчёте и **не вливайте в `main`**.

## 4. Структура репозитория
```
src/pages/*.html        шаблоны страниц (в начале — блок <!--page { JSON } -->: out, nav, title, description, schema, scripts, crumbs)
src/templates/bike.html шаблон страницы модели (генерируется для каждой записи каталога)
src/partials/*.html     layout, header, footer, cookie, overlays (прелоадер/тосты/курсор), calc
src/data/motorcycles.json  каталог моделей
site.config.json        бренд, телефон, адрес, реквизиты, домен, соцсети, коды верификации, noindex
scripts/build.mjs       генератор: *.html, bikes/*.html, sitemap.xml, robots.txt, site.webmanifest
scripts/lib/bikes-svg.mjs  SVG-силуэты мотоциклов (заглушки вместо фото)
scripts/check.mjs       проверки; scripts/serve.mjs — локальный сервер; scripts/make-og.mjs — og-image.png
css/                    tokens → base → layout → components → animations → pages
js/                     config, cookie, main, animations, forms, catalog, calc
assets/                 favicon.svg, logo.svg, og-image.png
*.html, bikes/*.html    РЕЗУЛЬТАТ СБОРКИ — руками не править!
```
Шаблонизатор: `{{path}}` — подстановка (значения экранируются; ключи на `…Html` и `content` — без экранирования), `{{> partial}}` — вставка, `{{@fn:arg}}` — функция из `FN` в `build.mjs`. `{{R}}` — префикс пути (`''` или `'../'`); во всех ссылках и ресурсах используйте `{{R}}`, пути только относительные.

## 5. Правила кода
- **Не править сгенерированные файлы** (`/*.html`, `bikes/*`, `sitemap.xml`, `robots.txt`, `site.webmanifest`) — они перезапишутся. Правьте `src/`, данные, конфиг или генератор.
- Новая страница: файл в `src/pages/` с блоком `<!--page … -->`, ссылка в `header.html`/`footer.html` при необходимости → `npm run build`. Один `<h1>` на странице, уникальные `title` (50–70 симв.) и `description` (120–160 симв.).
- Новая модель: добавьте объект в `src/data/motorcycles.json` (все поля как у существующих; `slug` — латиница-дефисы) → сборка создаст страницу, карточки, sitemap.
- **JS:** ванильный, без библиотек, в IIFE, `"use strict"`, всё через `defer`. Никаких внешних CDN, шрифтов и трекеров: сайт не должен делать сторонние запросы до согласия пользователя.
- **CSS:** только токены из `tokens.css` (`var(--…)`), мобильная адаптивность обязательна, цели нажатия ≥ 44–48 px, поля ввода ≥ 16 px (иначе iOS зумит), контраст AA (красный текст на тёмном — `--red-hot`).
- **Анимации:** только `transform`/`opacity`/`clip-path`; наблюдение через `IntersectionObserver`, циклы через `requestAnimationFrame`; обязательно уважать `prefers-reduced-motion` и класс `.is-lite` (слабые устройства). Скрытые состояния (`opacity:0` и т. п.) включаются только под классом `.js` на `<html>` и должны иметь «страховку», если JS не загрузился.
- **Доступность:** семантические теги, `aria-*` для меню/диалогов, видимый `:focus-visible`, `alt`/`aria-label` у содержательной графики, декоративное — `aria-hidden`.
- **Подводные камни:** при правке файлов скриптами не используйте `String.replace` со строкой-заменой, содержащей `$'`, `$&`, `$/` (это спецсимволы) — применяйте редактор файлов или функцию-замену. Не оставляйте в репозитории временные файлы (`_test*.html`, отладочные скрипты).

## 6. Контент и юридические правила (важно: сайт РФ)
- **Не выдумывать факты о компании:** нельзя писать недоказуемые «лучшие», «№1», гарантии, сроки, проценты, количества проданных мотоциклов, отзывы, награды, статус «официальный дилер». Неизвестное оформляйте заглушкой `<span class="ph">[что заполнить]</span>`.
- **Цены и условия** — всегда «ориентировочные / уточняйте у менеджера», не публичная оферта (ст. 437 ГК РФ). Калькулятор — только «предварительный расчёт, не является рекламой кредитного продукта»; ставка — условная (`js/config.js` → `calcRate`, `data-rate` в `calc.html`). Не указывать конкретные ставки/банки как реальные.
- **Персональные данные (152-ФЗ):** любая форма сбора ПДн должна иметь **отдельный, не отмеченный по умолчанию** чекбокс согласия со ссылкой на `consent.html` и `privacy.html`; без согласия отправка блокируется. Не собирать больше данных, чем нужно (имя, телефон, модель, комментарий). Не логировать ПДн в консоль, не класть их в URL.
- **Cookie:** необходимые — всегда; аналитика/маркетинг — только после согласия через `js/cookie.js`. Новые счётчики и пиксели подключать **только** через `IVAX_CONFIG` (`analytics`/`marketing`) — не вставлять `<script>` в шаблоны напрямую.
- **Права на материалы:** не копировать тексты, фото, логотипы и код чужих сайтов (elmoto74.ru, Avito и др.). Названия брендов — только для описания товара, без намёка на аффилированность.
- **Юридические документы** (`privacy`, `consent`, `terms`, `cookies`) — шаблоны. Не «улучшайте» формулировки самостоятельно и не удаляйте разделы; менять смысл можно только по указанию владельца/юриста. Поля `[…]` / `.ph` — заполняет владелец. Не подставляйте выдуманные ИНН, ОГРН, адреса, телефоны.
- **Не публиковать личные данные** владельца и партнёров (email, телефоны) в коде, кроме тех, что уже указаны в `site.config.json` для сайта.

## 7. Безопасность и процесс
- Секреты (токены, ключи API, пароли) **не коммитить** и не вставлять в код. `formEndpoint` в `js/config.js` — публичный URL обработчика, не секретный ключ.
- Не менять настройки репозитория (видимость, Pages, защита веток, collaborators) и не приглашать людей без прямого указания владельца.
- Не снимать `noindex` и не менять `domain` в `site.config.json` без указания владельца.
- Не устанавливать глобальные программы и не менять систему без необходимости; зависимости проекта — нулевые, не добавляйте npm-пакеты без согласования.
- Если требование неясно или противоречит этим правилам — остановитесь и задайте вопрос владельцу, а не угадывайте.
